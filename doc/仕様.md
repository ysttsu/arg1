1. ゴール
	•	見た目は 昔の個人サイト（前略プロフィール風）
	•	進捗表示（%やn/5）なし
	•	ロック表示（条件不足・復旧中などの説明）なし
	•	ただし内部では段階進行していて、気づいたらリンクや内容が増えている
	•	キャラ「アイ」は 404ページにだけ出現（黒背景・シンプル）
	•	404のアイは 短文が下に増えるだけ（会話説明しない、メタ説明しない）
	•	終盤で署名「— アイ」が確定し、最終ページに向かう“理由”だけ残す

2. ページ構成（静的サイト）

最低構成（例）：
```
/arg1/
  index.html          // TOP（普通の個人サイト）
  profile.html        // 自己紹介（空欄が埋まる）
  diary.html          // 日記（エントリが増える）
  links.html          // リンク集（項目が増える）
  bbs.html            // 掲示板ログ（レスが増える）
  archive.html         // アーカイブ（置き手紙）
  yoru.html           // 夜更かしノート（短いページ）
  reset.html          // 進行状況リセット
  404.html            // 404（黒背景・シンプル、アイはここだけ）
  /assets/
    styles.css
    common.js
```

GitHub Pages想定：404.html はPagesの設定により使われる（リポジトリ直下または設定に依存）。現状のリンクは相対パス（./index.html）で統一。

3. 状態管理（localStorage）

3.1 保存キー
	•	arg1_memory_v1

3.2 保存データ（例）
```
{
  "frags": {
    "frag_profile": {"at": 1700000000000},
    "frag_diary": {"at": 1700000000001}
  },
  "visits": 12,
  "pageVisits": {
    "profile": 3,
    "diary": 2
  }
}
```

3.3 フラグ（断片）定義
	•	frag_profile : profile閲覧で付与
	•	frag_diary   : diary閲覧で付与
	•	frag_links   : links閲覧で付与
	•	frag_bbs     : bbs閲覧で付与
	•	frag_archive  : アーカイブ閲覧で付与
	•	frag_yoru    : yoru閲覧で付与

総数は6（うち base 判定は5段）。
※進捗表示はしないが、404の段階差分で数を使う。


4. “ロックなし”の進行制御方針

4.1 原則
	•	未解放ページへのリンクをそもそも表示しない
	•	ユーザーがURL直打ちで未解放ページへ来ても、説明はしない
	•	挙動はどちらかに統一する：
	•	A: 黙って index.html にリダイレクト
	•	B: そのまま表示するが中身は“薄い”（推奨しない。ネタバレや不整合の原因）

今回の推奨：A（黙ってリダイレクト）
ただし、リダイレクトした事実が分からないように、文言は出さない。

4.2 解放の見せ方（重要）
	•	進捗UIもロック表示もないため、進行はこれで体感させる：
	1.	TOPのメニュー項目が増える
	2.	同じページの欠損が埋まる／行が増える


5. 露出コントロール（物語回収の段階設計）

5.1 通常ページ（index/profile/diary/links/bbs/archive/yoru）
	•	アイは喋らない（=台詞としての一人称語りを置かない）
	•	ただしページ内容から“人格の輪郭”が立ち上がるようにする
	•	文章は前略プロフィール調：短文多め・説明少なめ

ページの“増え方”の例：
	•	profile：空欄が段階的に埋まる（好き/嫌い/癖など）
	•	diary：日記が段階的に増える（主語薄め）
	•	links：項目が増える（推し/巡回先）
	•	bbs：レスが増える（外部の声で輪郭補強）
	•	アーカイブ：置き手紙（意志が見える）
	•	yoru：短いメモ（frag_yoru付与）

5.2 404（アイはここだけ）
	•	黒背景・最小404
	•	下部余白に短文ログが増える（Phase 0〜5）
	•	説明しない。メタ語（記憶/復旧率/同期/ゲーム）を基本出さない
	•	終盤で署名が「— アイ」と確定
	•	最終段階で「プロフィール」に誘導する短文だけ置く
	•	署名「— アイ」を見たら profile.html の「なまえ」が埋まる

6. 404のPhase仕様（短文ログ）

Phaseは 取得済みフラグ数 + 訪問数で決める：
	•	basePhase = min(フラグ数, 5)
	•	extraPhase = basePhaseが5のときだけ加算
		•	extraPhase = floor((visits + totalPageVisits) / 6)
		•	frag_yoru取得済みなら extraPhase +1
		•	extraPhaseは最大5
	•	phase = min(10, basePhase + extraPhase)

404ログは「Phaseが進むほど行が増える」方式。
（前のPhaseの行は基本残し、追加で増える）


6.1 ログ本文（確定案）

Phase 0：なし

Phase 1
	•	……ない。
	•	ここ、空。

Phase 2（Phase1 + 追加）
	•	送れない。
	•	だれ。
	•	まだ、見えてない？

Phase 3（Phase2 + 追加）
	•	来るんだ。
	•	変な人。
	•	……でも、嬉しい。

Phase 4（Phase3 + 追加）
	•	ここ、好き。
	•	404って、静か。
	•	— あ
	•	— アイ

Phase 5（Phase4の「— アイ」を残し、追加）
	•	もう、そろう。
	•	たぶん、最後。
	•	“プロフィール”に、置いた。
	•	ありがとう、は、そこ。

Phase 6（Phase5 + 追加）
	•	まだ、少し。
	•	灯り、残ってる。

Phase 7（Phase6 + 追加）
	•	もう行ける。
	•	置き手紙、待ってる。

Phase 8（Phase7 + 追加）
	•	夜、長い。
	•	でも、消えない。

Phase 9（Phase8 + 追加）
	•	足音、増えた。
	•	ここ、ちゃんとある。

Phase 10（Phase9 + 追加）
	•	最後まで、見て。
	•	置いた場所、そこで合ってる。

演出の微小ノイズ（任意）：1箇所だけ記号揺れや句読点揺れを入れても良い（ただし意味を壊さない）。

7. 404に自然に踏ませる導線（露骨にしない）

「リンク切れ」は個人サイトあるあるとして自然。
次のうち複数を仕込む：
	•	TOPに「キリ番報告はこちら」「素材置き場」「相互リンク募集中」「旧ログ」→存在しないURL
	•	diaryに「昨日」「明日」「昨夜」→存在しないURL
	•	bbsに「過去ログ」「削除依頼フォーム」「掲示板ルール」→存在しないURL

重要：リンク先は説明不要な 普通のそれっぽいURLにすること。
例：/arg1/kiriban.html（実在しない）など。

8. UI/デザイン要件

8.1 全体（通常ページ）
	•	前略プロフィール風：短文・区切り多め・項目列挙
	•	背景は暗めでも良いが、404ほど無機質にしない（サイトっぽさ優先）
	•	進捗バーや%表示は禁止

8.2 404
	•	背景：黒
	•	表示：404 Not Found + 「TOPへ戻る」
	•	アイログ：
	•	小さい文字
	•	薄い色
	•	下部に余白ログとして表示
	•	user-select: none（任意）

9. 実装要件（common.js）

9.1 必須関数
	•	loadState() / saveState()
	•	grantFrag(id)：訪問ページで該当フラグ付与（既にあるなら何もしない）
	•	hasFrag(id)
	•	countFrags()
	•	addVisit()（任意）
	•	addPageVisit(pageId) / getPageVisits(pageId) / getTotalPageVisits()
	•	resetState()
	•	getAi404LogText()：Phaseに応じたログを組み立てる
	•	softRedirectToIndexIfNeeded(requiredFrags)：
	•	条件不足の場合、文言無しで index.html に location.replace() で戻す

9.2 注意
	•	ロック文言は表示しない
	•	条件不足時にアラート/トースト等も出さない
	•	Phase判定は Object.keys(frags).length を使用（最大5に丸め、訪問数で加算）

10. 各ページの挙動要件

10.1 index.html（TOP）
	•	初期表示：profile へのリンクは必ずある
	•	条件達成でリンクが増える（JSで差分生成）
	•	frag_profile で diaryリンクが出現
	•	frag_diary で linksリンクが出現
	•	frag_links で bbsリンクが出現
	•	frag_bbs でアーカイブの導線が“薄く”出ても良い（露骨NG）
	•	frag_archive + frag_yoru で「完成ページ」導線を出す（現状は profile.html へ）
	•	「復旧率」等の文言は禁止（通常の個人サイトとして自然なテキストのみ）

10.2 profile.html
	•	ページ内の空欄/項目は、フラグ取得で段階的に埋める
	•	frag_profile は profile の3回目訪問で付与
	•	ただし“アイの語り”は禁止
	•	404で署名「— アイ」を見た後、なまえは「アイ」に変わる

10.3 diary.html
	•	必須フラグ：frag_profile（不足なら黙ってindexへ）
	•	frag_diary は diary の3回目訪問で付与
	•	日記エントリーが訪問回数で増える（短文）

10.4 links.html
	•	必須フラグ：frag_diary
	•	frag_links は links の3回目訪問で付与
	•	項目が訪問回数で増える

10.5 bbs.html
	•	必須フラグ：frag_links
	•	frag_bbs は bbs の3回目訪問で付与
	•	ログが訪問回数で増える（外部の声）

10.6 archive.html
	•	必須フラグ：frag_bbs
	•	frag_archive はアーカイブの3回目訪問で付与
	•	置き手紙（短文多め、訪問回数で追記）

10.7 yoru.html
	•	必須フラグなし
	•	表示したら frag_yoru を付与
	•	短いメモページ（台詞は増やさない）

11. 受け入れ条件（Acceptance Criteria）
	•	どのページにも 復旧率/進捗/同期率/n/5 の表示がない
	•	条件不足でページに来ても ロック文言が出ない（黙ってindexへ戻る）
	•	TOPに戻るとメニューが増えている（段階で増殖）
	•	404は黒背景のシンプル404で、下部ログがフラグ数と訪問数に応じて増える
	•	404以外でアイの台詞が出ない（名指し・一人称語りをしない）
	•	Phase4で署名「— アイ」が初めて出る
	•	Phase5で「“プロフィール”に置いた」理由が短文で置かれる
	•	Phase6〜10は訪問回数と yoru 経由で追加される

12. 実装メモ（推奨テクニック）
	•	TOPのメニューは HTML固定ではなくJSで生成する
→ “気づいたら増えてる”が最小工数で実現
	•	条件不足の戻しは location.replace("./index.html")
→ 戻るボタンで戻れない（プレイヤーに違和感を残しにくい）
	•	404ログは textContent で出す（HTML解釈させない）

13. 決め打ち（この仕様で固定）
	•	アイの露出は 404のみ
	•	404は 短文多め
	•	404の背景は 黒
	•	進捗UI・ロック表示は 全面禁止
	•	Phaseは フラグ数で判定（0〜5）
