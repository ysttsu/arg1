0) 用語・概念

0.1 断片フラグ（内部用）
	•	frag_profile / frag_diary / frag_links / frag_bbs / frag_archive / frag_yoru
	•	基本5フラグ（profile～アーカイブ）+ ボーナス1フラグ（yoru）= 計6フラグ
	•	404のPhase進行は基本5フラグで0〜5、その後訪問回数で6〜10へ拡張

0.2 訪問回数
	•	visits：グローバル訪問カウンター（全ページ共通）
	•	pageVisits：ページ別訪問回数（profile, diary, links, bbs, archive, yoru 個別）
	•	表示差分の条件は「フラグ取得済み」または「訪問回数N回目」で記載

0.3 完成ページの概念
	•	「完成ページ」とは、全フラグ収集後のprofile.htmlを指す
	•	frag_archive + frag_yoru 取得済みでindex.htmlのメニューに出現
	•	profile.htmlが段階的に埋まり、全項目が表示された状態が「完成」
	•	※ただし「なまえ」項目は最後まで「――――」のまま（意図的）

0.4 yoru.htmlの発見方法
	•	diary.htmlの訪問4回目で表示される「メモ」セクションが謎解き
	•	縦読み・頭文字拾いで「yoru.html」を示唆
	•	直接リンクはなく、URLを推測して訪問する隠しページ

0.5 推奨プレイフロー（想定される体験）

基本サイクル：「新ページ探索 → フラグ取得 → profileで変化確認」

	1.	index.html訪問 → profile.htmlへ（常時表示）
	2.	profile を3回訪問 → frag_profile 取得
	3.	**index に戻ると diary リンク出現** → diary へ
	4.	diary を3回訪問 → frag_diary 取得
	5.	**profile に戻ると「性格」「くせ」が埋まる**（1回目の変化確認）
	6.	**index に戻ると links リンク出現** → links へ
	7.	links を3回訪問 → frag_links 取得
	8.	**profile に戻ると「すき」が埋まる**（2回目の変化確認）
	9.	**index に戻ると bbs リンク出現** → bbs へ
	10.	bbs を3回訪問 → frag_bbs 取得
	11.	**profile に戻ると「きらい」「ひとこと」が埋まる**（3回目の変化確認）
	12.	**index に戻るとアーカイブリンク出現** → アーカイブへ
	13.	アーカイブを3回訪問 → frag_archive 取得
	14.	**profile に戻ると「ひとこと」が更新される**（4回目の変化確認）
	15.	diary 4回目訪問 → 謎解き「メモ」出現 → yoru.html を推測
	16.	yoru.html を訪問 → frag_yoru 取得（ボーナス）
	17.	frag_archive + frag_yoru 取得済み → **index に「完成ページ」出現**
	18.	**profile.html（完成ページ）で全項目が埋まった最終状態を確認**
	19.	404ページを複数回訪問 → Phase 1〜10 のメッセージ進行を体験

プレイ体験の設計意図：
	•	**フラグ取得後、必ずprofileに戻る動機を作る**（変化の確認）
	•	**index → 新ページ → profile → index**という循環構造
	•	profileが「進捗ダッシュボード」の役割を果たす
	•	リンク切れ（404）は自然に踏む設計（キリ番報告、昨日、過去ログなど）
	•	404のPhase進行は訪問回数でも進むため、周回することで最終Phaseへ到達

8) 404.html（黒背景・シンプル / アイはここだけ"発話"）

404本文は普通。
下の「余白ログ」だけが増える。
ここだけは"発話"扱いOK（短文、説明なし）。

固定404本文（常時）
	•	H1: 404 Not Found
	•	P: お探しのページは見つかりませんでした。
	•	LINK: TOPへ戻る → index.html

Phase条件（詳細）
	•	basePhase = min(取得済みフラグ数, 5)
		○	フラグ0個 → Phase 0（表示なし）
		○	フラグ1個 → Phase 1
		○	フラグ2個 → Phase 2
		○	フラグ3個 → Phase 3
		○	フラグ4個 → Phase 4
		○	フラグ5個以上 → Phase 5（+ extraPhase計算）
	•	extraPhase（basePhase === 5 のときのみ計算）
		○	extraPhase = floor((visits + totalPageVisits) / 6)
		○	frag_yoru取得済みなら extraPhase +1
		○	extraPhaseは最大5に制限
	•	最終Phase = min(10, basePhase + extraPhase)

Phase構造の特徴
	•	Phase 0〜5：フラグ収集で進行（メインストーリー）
	•	Phase 6〜10：全フラグ収集後、訪問回数で進行（エクストラ）
	•	Phase 4で署名「— アイ」が確定
	•	Phase 5で"プロフィール"への誘導
	•	Phase 6〜10は frag_yoru 取得が実質必須（extraPhase加算のため）

アイ余白ログ（Phase 0〜10）


10) 実装上の注意事項（開発者向け）

10.1 DOM操作の方針
	•	文章をそのまま固定で入れつつ、差分はJSでDOM差し替えで実現する
	•	index.htmlのMENUはJSで生成（条件で項目を追加）
	•	profile.htmlはspan要素の中身を条件で差し替え（getElementById + textContent）
	•	diary/links/bbs/archiveはブロック単位でJSで追加（createElement + appendChild）
	•	条件不足アクセス時は 黙ってindexへ location.replace（テキスト表示しない）

10.2 フラグ付与タイミング
	•	各ページで addPageVisit(pageId) を呼び、訪問回数をカウント
	•	3回目の訪問で grantFrag() を実行（profile, diary, links, bbs, archive）
	•	yoru.htmlのみ初回訪問で即座にfrag_yoru付与
	•	フラグ付与後も訪問回数は増え続け、追加コンテンツ表示に使用

10.3 404のPhase実装
	•	common.jsの getAi404LogText() 関数で全Phase分岐を実装済み
	•	Phase 0〜5は countFrags() で判定
	•	Phase 6〜10は extraPhase 計算（visits + totalPageVisits の合計 ÷ 6 + yoru加算）
	•	Phase 5で「— あ」を削除し「— アイ」のみにする処理を実装

10.4 完成ページ（profile.html）の扱い
	•	frag_archive + frag_yoru 両方取得済みでindex.htmlに「完成ページ」リンク出現
	•	リンク先は profile.html（別ページではない）
	•	profile.htmlを訪問すると、全フラグ状態で空欄が埋まっている状態を確認できる
	•	「なまえ：――――」だけは最後まで埋まらない（意図的な余白）

10.5 謎解き（yoru.html発見）の実装
	•	diary.htmlの訪問4回目で「メモ」ブロックを表示
	•	メモの各行の1文字目を拾うと「よるうら,ひとみら」→「yoru.html」
	•	直接リンクは貼らず、ユーザーが自力でURL推測して訪問する設計
	•	yoru.html自体は通常ページとして実装（必須フラグなし、即座にfrag_yoru付与）

10.6 デバッグ・テスト
	•	localStorage確認：window.Arg1.loadState() で現在状態を確認
	•	フラグ手動付与：window.Arg1.grantFrag("frag_profile") など
	•	リセット：reset.htmlを使用、または localStorage.clear()
	•	Phase確認：window.Arg1.getAi404LogText() で現在の404メッセージを確認

10.7 セリフ・テキストの設計意図（重要）
	•	404のPhase進行は「孤独→気づき→喜び→安心→完成→継続」の感情変化
	•	Phase 1-3: 孤独から訪問者への気づき、「消えないで、ね。」で懇願
	•	Phase 4: 「でも、あなたは来る。」で信頼の確立、名乗り
	•	Phase 5: 「見てくれた分だけ、形になった。」で訪問者の貢献を明示
	•	Phase 5: 「"プロフィール"に、全部置いた。会いに来て。」で直接的な訪問促進
	•	Phase 6-10: 完成後も訪れ続けることへの驚きと深い感謝
	•	最終Phase: 「また、ね。」で余韻と継続性を残す
	•	profile.htmlの「ひとこと」: 「最後まで見てて」→「最後まで、置いとく」で呼応
	•	archive.htmlのメモ: 「手を、離さない」→「最後まで、残す」で決意の強化
	•	全体を通じて、訪問者とアイの相互作用が「形」を作るインタラクティブな物語

10.8 profileへの回帰体験の設計（循環構造）
	•	**基本サイクル：「新ページ探索 → フラグ取得 → profileで変化確認」**
	•	profileは「進捗ダッシュボード」の役割を果たす
	•	フラグ取得後、profileに戻る動機：
		○	index.htmlの「自己紹介（とりあえず）」が「追記するかも」の雰囲気を出す
		○	404のPhase 5で「"プロフィール"に、全部置いた。会いに来て。」と直接誘導
		○	各ページでフラグ取得後、「自己紹介を見に行こう」という自然な流れ
	•	実装上の注意：
		○	profile.htmlの項目埋めは「フラグベース」
		○	基本的にはフラグを取得してprofileに戻ることで変化を発見する設計
	•	変化のサプライズ：
		○	フラグ取得後、profileに戻ると「あ、埋まってる！」という発見の喜び
		○	4回の変化（diary→links→bbs→archive）で段階的に人格が明らかに
		○	最終的に「なまえ」以外が全て埋まり、404で「— アイ」として完結
